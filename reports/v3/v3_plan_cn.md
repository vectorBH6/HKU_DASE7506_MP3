# 第三轮：拒绝提议后的恢复实验

本轮先隔离控制器因素，不训练新权重。基座和 adapter 均沿用第二轮：Qwen/Qwen3-0.6B@c1899de289a04d12100db370d81485cdf75e47ca，单个未合并 onpolicy_v001/epoch_02，adapter SHA-256 43d91619f16b1a7e4cb3358ad93cfc5f8ee447ff124640a8b5e2ff8ee44de613。

假设：v2 在提议被拒绝后，可能在预算未尽时回退提交；给模型明确的拒绝记录和一次有界恢复机会，可以改善纠错。只在发生拒绝之后扩充上下文，首次及未拒绝路径保持 v2 提示。新增上下文仅由官方 observation 和自身提议、校验结果导出，包括最近两次拒绝、最近 SQL 错误及剩余生成预算。Agent 自行维护这些记录，不修改官方 observation/trace。

- e20_recovery4：风险复核、最多4次生成、每次384新token；同一 observation 内至多一次恢复生成，第二次输入必须包含新拒绝信息。
- e21_recovery6：与 e20 完全相同，仅将生成上限改为6。
- 基线为第二轮 e13_review_risk 验证 87/120、e15_review_selected 测试181/240，旧预测、评分和配置保留。
- 原稿精确 check、schema、候选提交保护、SQL解析、工具预算和原有有限回退保持；不新增官方工具，不访问评分参考或额外数据库。
- 全部正式评测仍为四核CPU、workers=1、离线、16GiB RSS、预测2小时/评分180秒。同一 .venv，不创建 peer_reviews 或 dist，不上传。

选择规则在本轮验证评分产生前固定：先完成两组120题验证。新方案按正确题数最多选择，并列优先模型调用少、再按实验名稳定排序；只有严格超过87/120才替换项目默认，平局保留v2。无论是否替换默认，都锁定最佳新方案并进行一次完整240题测试以报告比较，测试成绩不用于重新选择。停止/恢复与生成预算是本轮两项受控比较，报告改善、退步、重复提议、恢复成功、资源成本及公开匹配误判。

本轮不使用测试题目、答案或评分指纹生成训练材料；所有变更均为通用控制器规则。官方程序和数据保持不变。后续训练优化待本轮结论明确后另做实验。
