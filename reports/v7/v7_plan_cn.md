# V7 实验设计 · 同一份 SQL 草稿与两种题意

本轮检验一项数据处理方法。对于数错实体、JOIN 放大行数和边界比较三类错误，构造两种自然语言意图和同一条草稿。一个意图应保留原稿，另一个需要修复。相同公开示例允许两条 SQL 碰巧同答，独立设计的微型数据库用于区分两条 SQL。训练和微型数据只从官方 train 派生，每条记录保留来源并区分合成和实测轨迹。官方数据库及评分器保持原样。

- 基线为 V4b 的 contract_v4 和 onpolicy_v001/epoch_02。
- 普通扰动与配对数据两组分别从同一适配器初始化。固定控制器、学习率、种子、轮数、实际训练样本数和优化步数。两组共享普通回放。按预先确定的训练集数据库划分形成增量留出集。报告样本、独立题对、数据库数及训练时的标签分布。
- 专项主要指标为同一题对中两条最终 SQL 同时正确的比例。分别报告保留正确稿和修复错误稿，注明判定所用实例及合成工具设定。历史基线见过官方 train，留出限定在本轮派生数据。
- 两组都使用 epoch_01 固定权重。无论专项、验证结果如何，两组均用官方入口分别运行 120 道验证和 240 道公开测试。采用离线、四线程 CPU、每题最多 4 次生成、384 个新 token 与 8 次计费工具。基线复用相同配置的 e50 验证及 e42 测试和已完成的复评。完成两组训练后记录权重与控制器哈希。
- 除总分外，按原稿的三实例评分和首次公共检查分组，计算保住的正确原稿、修正的错误原稿，以及在原稿公开匹配时修正隐蔽错误的比例。报告相对 V4b 的修对/改错数，以及配对组相对普通扰动组的逐题变化。公开测试仅用于本次锁定权重的终点评估，不用于新增样本或调整训练。
