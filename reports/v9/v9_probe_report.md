# SQL 纠错实验记录

在 V8 的 120 道完整验证轨迹上重放工具反馈，按官方三个数据库实例核对最终 SQL。两项改动合用后从 96/120（80.00%）升至 98/120（81.67%）。这是开发阶段的验证结果。本轮未运行公开测试，当前项目已取得的最好公开测试成绩为 V8 的 189/240（78.75%）。[V8 正式评分](../../runs/e82_v8_struct/test/r001/score.json)

**公开示例通过但 SQL 仍然错。** 从 382 道训练题学习问法与 SQL 运算的关联。当原答案违背这些线索、且通过公开检查的其他候选中恰有一个符合时，才换答案。验证中多修对一道要求同时满足两个条件的题，16 道公开检查通过的错误草稿由修对 10 道升至 11 道。98 道留出训练题的 392 条旧轨迹中只触发一次，正确数维持 346/392。每题有四条历史轨迹。[验证消融](v9_intent_probe.json) · [留出数据库复查](v9_intent_history.json)

**输出列多于题目要求。** 当所有已试 SQL 均未匹配公开结果，若有 SQL 能运行、行数吻合且所需列都能唯一定位，就保留原查询，在外层选取所需列，再花一次工具调用检查。有顺序要求时，当前规则只处理显式限取一行的查询。这条规则来自对验证错题的观察。两道题触发且都匹配了空的公开结果，仅一道通过全部三个实例。两项合用共改动三道题的最终 SQL，保住 46/47 份原本正确的草稿，与 V8 相同。总工具调用从 550 增至 552，单题最多 8 次，没有新增模型生成。[修复细节](v9_wrapper_probe.json) · [组合结果](v9_intent_probe.json)

**扩大训练数据。** 从 1,920 条旧训练轨迹补入 385 条去重候选，其中 307 条进入拟合，其余用于训练集内留出评估。在同一留出候选池上，重训选择器把 91/98 提到 93/98。在完整验证轨迹上，三道题换了答案，其中两道由对变错。保留现有 V8 选择器。[数据增补与逐题对照](../../runs/v9_trace_choose/results.json)

**增加生成和搜索。** 同一模型额外生成 86 次，验证净增 0 题。在另一个实验中，对八道尚有检查预算的失败题逐题枚举子句重组，一共评估了 52 个独立备选，全部未通过三实例评分。[模型复判与重写](v9_terminal_probe.json) · [子句重组覆盖率](../../runs/v9_clause_probe/upper_bound.json)

下一项值得验证的是把两条规则固定后接入正常推理入口，从头运行，与 V8 比较逐题修对和改错。留出数据库尚未复现这两题的收益，目前保留 V8 作为已有正式成绩的版本。
