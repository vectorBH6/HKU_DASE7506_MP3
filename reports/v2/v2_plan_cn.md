# 第二轮实验方案与规则核对

旧方案、旧 adapter 和全部既有预测/评分保留。当前默认不切换；待验证集比较后选择。

新控制器先原样 check 原稿、读取 schema，然后由 Qwen 输出短 JSON，提出 check / execute / repair_hint / retrieve / submit 动作。提交选择已经 check 的候选；Python 负责校验与预算，不把模型自评当作正确证明。公开示例匹配后仍进行语义复核，候选及其真实反馈一并给模型比较。

规则依据：官方 README 第 4、5 节允许修改控制器、提示、工具决策和候选选择，也允许在指定 Qwen3-0.6B revision 上仅训练 LoRA A/B。

- 只返回现有官方动作，字段由 Python 转换为协议格式；不修改官方源码、数据、observation 或轨迹。
- 每题最多 8 次收费工具，submit 免费；原稿 check 在 repair_hint 之前；相同动作不重复。
- 每题最多 4 次模型生成，每次最多 384 新 token，低于官方 6 次/2048 token 上限；规划和复核也计入生成次数，完整记录提示、文本、token 与模型身份。
- 推理只通过官方工具访问公开数据库，Agent 不读评分参考或额外实例；train 的官方评分可用于离线训练监督。
- 新数据仅由 train 的旧模型自身轨迹、真实官方反馈和 train_memory 的 gold SQL 构造，不使用 validation/test 标签训练。
- 单个未合并模型，固定官方 revision；只训练 LoRA A/B，基座/tokenizer 不变。GPU 只用于训练和训练集采集；正式评测 CPU 四核、workers=1、离线，监测 16 GiB RSS 和两小时预测上限。
- 使用同一个 .venv；不创建 peer_reviews 或 dist，不执行上传。

预设对照：旧方案 e03；新控制器+旧 adapter；相同新控制器+新 on-policy adapter。新控制器另比较 always/risk/off 原稿匹配后复核策略（后续候选仍由模型比较）（验证集）。依据验证集选型，固定配置后评测完整测试集；不根据测试成绩重新调整规则。至少报告权重和停止策略两种受控对照，包含运行成本、退步案例和工具动作比例。

选择细则（在新 adapter 验证评分产生前固定）：新策略按验证集正确题数最多选择；并列优先模型生成总次数更少，再按配置名稳定排序。只有超过第一轮验证集 81/120 才替换默认方案，并列保留第一轮。测试成绩不参与选择。
